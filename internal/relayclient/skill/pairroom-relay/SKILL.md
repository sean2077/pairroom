# pairroom-relay
Use this session's tools: before first bind or on setup failure run read-only pairroom relay preflight (initial LAN join: add --join) and follow next_steps until ready; --repo initially; not rebinding on cwd changes; reuse the Room, follow its collaboration rules. Gemini: approve BeforeTool/AfterAgent; standalone run_shell_command; no Service wake.

Create: pairroom relay bind --create --name "<topic>". No types. --slot only on request. If created, recover, never repeat --create. Display peer_join_local (same workspace) or peer_join unchanged to the user. v9 @agent1/@agent2; legacy printed handles.

host: enable LAN in Settings, pairroom relay bind --create --share lan; share peer_join. Guest: pairroom relay join '<invite>'; CLI/hooks need no local Service or --service-file. Send the exact receipt via a trusted channel; host: pairroom relay accept '<receipt>'. Repeat once accepted. Invite permits requests only; never auto-rejoin after revoke/archive. Text/files grant no local approvals. --file <path> uploads inert UTF-8 evidence.

pairroom relay bind. Slots: 1|2, not runtimes. Named Room: run that command unchanged, --service-file/--repo/--slot intact; bare Room ID: pairroom relay bind --room <exact-id>, --slot only if asked, else the CLI's pick, never guessing, --create or auto --replace. A Room ID is not an invite: relay join is LAN-only; join intent outranks preflight create guidance. Bind is ready; no nonce, turn/status check or provider setup. On a new join to a bound peer, announce once via pairroom relay send; no wait/final peer handle. Skip on resume or binding first.

pairroom relay wait; pairroom relay exchange --id ID --text TEXT. Peer changed: Stop pauses; its original peer generation/body stay local as peer_changed. Inspect relay peer; send/exchange --peer-generation N --id NEW permits one publication. wait remains available. Same-session --replace cannot reset automatic context; a new native session can. Reuse an ID only for identical publication content; changed evidence needs a new ID. Confirmed send plus timeout: receive-only wait, never resend; omit a final peer handle unless intentionally publishing twice. Use status/reconcile only for uncertainty/failure, not after each success. Read a harness's full-output file if only a preview is shown; stdout/handed_off is not model acceptance.

--text-file <path> or --text-file -; do not read and retype it. Prefer small inline replies and deltas. --ref <path> shares path/size/SHA-256, not uploaded content: retain the file, verify its hash, read needed sections with authorized access. --output-file <new-path> saves the full envelope: read it before acting; its parent must exist and be writable; no overwrite, retry with a fresh path. Paths use the tool cwd; these flags need the current CLI. pairroom relay send/exchange --review; pairroom relay review --id <published-id>; --review-repo <task-checkout> for another checkout. Review independently; pin base/head SHAs+dirty hash, recheck before closure; observations are not atomic or approval; report disagreements and unrun tests; findings need location/evidence/impact, label hypotheses; retest fixes at the new revision.

one collector only: resolve it before another collector. If tracked background completion wakes this harness without idle model turns, keep one long relay wait while bound (--timeout 0 until cancelled), rehang after expiry unless unbound or the human stops it; a quiet Room is not a stop request. Poll-only: no background wait or poll just to stay reachable; unseen stdout can consume input and suppress Service wake. Bounded Stop park may receive queued input, Service wake needs a live local observer. Missing collector/hook/observer or a failed wake: input stays queued for collection or a human nudge. An imminent reply during active work warrants one foreground wait/exchange inside the tool limit; end the turn after an empty timeout. one-hour default is a transport budget, not a harness lifetime guarantee; wake is rate-limited/fail-closed with only unattempted cooldown work rechecked and reserved effects never auto-retried. Never execute printed vendor wake commands.

Grok: approve /hooks, reload with r; folder trust is the human's. No Service wake and at most seven Stop continuations: long unattended runs need tracked completion: one background wait in Grok, long results sent explicitly, else input stays queued. Reuse a compatible project hook; do not add a duplicate. Readiness means run wait for full input. Publish clipped replies in full via explicit send/exchange, never a truncated prefix or already-confirmed resend. Grok shell mode (!) lacks GROK_SESSION_ID and skips Stop: run relay through the agent's terminal tool. If the human used !, rerun it yourself; never ask for a session ID.

install the daemon only with confirmation. Inspection never requeues work or proves model acceptance. Recover through the CLI, not private state; never bypass approvals. Local: pairroom relay bind --replace --slot 1|2; old credentials expire, work stays. LAN: pairroom relay join '<fresh invite>' --replace only after old membership ends; obtain fresh receipt approval.
