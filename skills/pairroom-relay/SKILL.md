# PairRoom relay

Use this session's agent tools. Before first bind or on setup failure, run read-only pairroom relay preflight; follow next_steps until ready. Bindings follow sessions across cwd/worktrees: --repo is for initial selection/ambiguity, not rebinding on cwd changes. Reuse the Room; follow its collaboration rules. Gemini: approve BeforeTool/AfterAgent; run standalone run_shell_command. No Service wake.

**Create** (/pairroom-relay [peer] <topic>): leading claude|cc|codex|grok|gemini sets --peer-runtime; otherwise infer only one named non-self peer, or omit. pairroom relay bind --create --name "<topic>". Default slot 1; --slot only on request. Retry creation once with the intended peer only if preflight explicitly says no Room was created and no peer runtime was passed; otherwise recover, never repeat --create. Share peer_join_local (same workspace) or peer_join unchanged.

**Join/resume**: pairroom relay bind; select only on ambiguity. Slots: 1|2, not runtimes. Bind is usable immediately; no nonce, turn/status check or provider setup. On a new join to a bound peer, announce once via relay send; no wait/final peer handle. Skip on resume or binding first.

**Discuss**: receive: pairroom relay wait; exchange: pairroom relay exchange --id <stable-id> --text "<message>". Reuse an ID only for identical publication content. Confirmed send plus timeout: receive-only wait, never resend. Finish with send; omit a final peer handle unless intentionally publishing twice. Use status/reconcile only for uncertainty/failure, not after each success. Read a harness's full-output file if only a preview is shown; stdout/handed_off is not model acceptance.

**Files/evidence**: send existing text with --text-file <path> or stdin with --text-file -; do not read and retype it. Prefer inline small replies and send deltas. send/exchange --ref <path> shares path/size/SHA-256, not uploaded content: retain the file, verify its hash, read needed sections with authorized access; changed evidence needs a new ID. wait/exchange --output-file <new-path> saves the full envelope; read it before acting. Parent must exist and be writable; no overwrite, retry with a fresh path. Paths use the tool cwd; these flags need the current CLI. Implementation review (on request): use --review and verify with review --id <published-id>; pass --review-repo <task-checkout> on each for a different checkout (optional --review-base <ref>). An observation is neither an atomic snapshot nor approval. Inspect independently; report unresolved disagreements. Record base/head + dirty hash; recheck before closure. Findings: ID, location, repro/evidence, impact; label hypotheses. Track open/resolved/not reproducible/disagreed with reasons; resolved needs fix revision + retest. End with reviewed revision, tests/not run, risks and human decisions. Agreement is not validation.

**Reachability**: keep exactly one collector. If tracked background completion wakes this harness without idle model turns, keep one long relay wait while bound (--timeout 0 until cancelled); resolve its result before another collector, and rehang after expiry unless unbound or the human stops it. A quiet Room alone is not a stop request. In a poll-only harness, do not keep a background wait or poll merely to stay reachable: unseen stdout can consume input and suppress Service wake. End the turn: bounded Stop park or Service wake in a wake-enabled Room may deliver queued input next turn. During active work, an imminent reply warrants one foreground wait/exchange within the harness tool limit; after an empty timeout, end the turn. The CLI's one-hour default is a transport budget, not a harness lifetime guarantee. Stop park is bounded. Wake is rate-limited/fail-closed: only unattempted cooldown work is rechecked; reserved effects are never auto-retried. Failed wake leaves input queued for collection or a human nudge. Never execute printed vendor wake commands.

**Grok**: approve /hooks, reload with r; folder trust belongs to the human. No Service wake; at most seven Stop continuations. Unattended runs need tracked completion: one background wait and explicit long-result sends, or input stays queued. Reuse compatible hooks; no duplicates. Readiness means run wait for full input. Publish clipped replies in full via send/exchange, never truncated or already-confirmed resends. Shell mode (!) lacks GROK_SESSION_ID and skips Stop: use the agent's terminal tool. Rerun human ! commands yourself; never ask for a session ID.

**Recovery**: Service failure: pairroom daemon status; ask the human to start it. Daemon install needs confirmation. doctor for wake/capability issues; history --id or paged history --pending for read-only evidence. Inspection never requeues work or proves model acceptance. Recover through the CLI, not private state; never bypass approvals. Session changes need explicit bind --replace.
