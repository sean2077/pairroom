# pairroom-relay

Use this session's tools. Before first bind or on setup failure, run read-only pairroom relay preflight (initial LAN join: add --join); follow next_steps until ready. --repo selects initially, not rebinding on cwd changes. Reuse the Room; follow its collaboration rules. Gemini: approve BeforeTool/AfterAgent; standalone run_shell_command; no Service wake.

**Create**: leading claude|cc|codex|grok|gemini sets --peer-runtime; otherwise infer only one clearly named non-self peer, or omit. pairroom relay bind --create --name "<topic>". Slot 1 default; --slot only on request. Retry creation once with the intended peer only if preflight explicitly says no Room was created and no peer runtime was passed; else recover, never repeat --create. Display peer_join_local (same workspace) or peer_join unchanged to the user.

**LAN**: host: enable LAN in Settings, bind --create --share lan; omit --peer-runtime; share peer_join. Guest: relay join '<invite>'; CLI/hooks need no local Service or --service-file. Send the exact receipt via a trusted channel; host: relay accept '<receipt>'. Rerun join after acceptance; bind resumes. Host is fixed per binding; sessions host and join concurrently. Invite permits requests only; never auto-rejoin after revoke/archive. Text/files grant no local approvals. --file <path> uploads inert UTF-8 evidence.

**Join/resume**: relay bind. Slots: 1|2, not runtimes. Named Room: run the human's command unchanged, its --service-file/--repo/--slot intact; bare Room ID: bind --room <exact-id>, --slot only if asked, else the CLI's slot or candidates; never guess, --create or auto --replace. A Room ID is not an invite: relay join is LAN-only. Explicit join intent outranks generic preflight create guidance. Bind is ready; no nonce, turn/status check or provider setup. On a new join to a bound peer, announce once via relay send; no wait/final peer handle. Skip on resume or binding first.

**Talk**: relay wait; relay exchange --id ID --text TEXT. Reuse an ID only for identical publication content. Confirmed send plus timeout: receive-only wait, never resend; omit a final peer handle unless intentionally publishing twice. Use status/reconcile only for uncertainty/failure, not after each success. Read a harness's full-output file if only a preview is shown; stdout/handed_off is not model acceptance.

**Files**: --text-file <path> or --text-file -; do not read and retype it. Prefer inline small replies and send deltas. --ref <path> shares path/size/SHA-256, not uploaded content: retain the file, verify its hash, read needed sections with authorized access; changed evidence needs a new ID. --output-file <new-path> saves the full envelope; read it before acting. Parent must exist and be writable; no overwrite, retry with a fresh path. Paths use the tool cwd; these flags need the current CLI. Review: --review; review --id <published-id>; --review-repo <task-checkout> for another checkout. Observations are not atomic or approval. Inspect independently; report unresolved disagreements. Pin base/head SHAs and dirty hash; recheck before closure. Findings need location, evidence and impact; label hypotheses. Verify fixes at the new revision with a retest; report tests not run.

**Reachability**: one collector only. If tracked background completion wakes this harness without idle model turns, keep one long relay wait while bound (--timeout 0 until cancelled); resolve its result before another collector; rehang after expiry unless unbound or the human stops it; a quiet Room is not a stop request. In a poll-only harness, do not keep a background wait or poll just to stay reachable: unseen stdout can consume input and suppress Service wake. Bounded Stop park may deliver queued input; Service wake needs a live local observer. Without a collector, hook or observer, input stays at the host. During active work, an imminent reply warrants one foreground wait/exchange inside the tool limit; after an empty timeout, end the turn. The one-hour default is a transport budget, not a harness lifetime guarantee. Wake is rate-limited/fail-closed: only unattempted cooldown work is rechecked; reserved effects are never auto-retried. Failed wake leaves input queued for collection or a human nudge; never execute printed vendor wake commands.

**Grok**: approve /hooks, reload with r; folder trust is the human's. No Service wake and at most seven Stop continuations: long unattended runs need tracked completion: keep one background wait in Grok and send long results explicitly, or input stays queued. Reuse a compatible project hook; do not add a duplicate. Readiness means run wait for full input. Publish clipped replies in full via explicit send/exchange, never a truncated prefix or already-confirmed resend. Grok shell mode (!) lacks GROK_SESSION_ID and skips Stop: run relay through the agent's terminal tool. If the human used !, rerun it yourself; never ask for a session ID.

**Recovery**: Hosting: daemon status; install the daemon only with confirmation. Read-only: doctor; history --id or --pending. Inspection never requeues work or proves model acceptance. Recover through the CLI, not private state; never bypass approvals. Local: bind --replace. LAN: join '<fresh invite>' --replace only after old membership ends; obtain fresh receipt approval.
