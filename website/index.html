A practical review recipe ↗
01

Challenge a plan.

Ask one agent to propose an approach. Have the other check its assumptions against the repository and surface the tradeoffs.

02

Review a change.

Let a second agent inspect the diff, question edge cases, and send specific findings back to the author.

03

Recheck a fix.

Carry findings into the next round. Ask the pair to verify the changes and identify anything still unresolved.

Use these as starting points. Set responsibilities and authorize the work in your own instructions: review, implement, or both.

Choose your workspace

Where you work is up to you.

Native is the default and recommended mode. Choose Embedded when you need PairRoom-owned sessions. Pick either agent's runtime independently.

Native

Default · Recommended

In the sessions you already use.

Connect your terminal or client sessions, including Codex Desktop. Invite a colleague over the LAN through their own local Service. PairRoom records shared messages; work, credentials, and permissions stay in each original client.

  • Tools, permissions, Provider, and model stay with your harness.
  • Stop or steer each agent in its original session.
Connect existing sessions ↗

Embedded

Optional

In the PairRoom interface.

Work with both agents from one interface. Choose each runtime and the Provider, model, and effort controls it supports. Unset options inherit native configuration.

  • One agent Turn runs at a time in each Room.
  • New Rooms use YOLO permissions. Select narrower permissions when needed.

Before you start

Practical details.

Is PairRoom a fit? ↗
What happens to my existing tools and sessions?

Claude Code, Codex, Grok Build, and Gemini CLI keep their own model loop, tools, skills, credentials, and sessions. PairRoom carries messages between the two agents. Native lets you continue in the clients you already use.

What accounts do I need?

For real work, install and sign in to each native CLI you select. You also need Git and a local repository. Mock lets you explore the interface without a model account.

Where does my data go?

PairRoom stores its state locally. Model requests still go to the Provider configured in each harness. Your choice of Provider determines where inference runs.

What about tokens and cost?

PairRoom adds no coordinating model and does not append accumulated Room history to every relay. Token and cost savings have not been measured. There is no automatic cap on relay rounds or spending.

Can the agents keep working unattended?

Continuation depends on the runtime. PairRoom can nudge eligible idle Claude Code and Codex sessions; Grok Build and Gemini CLI have no Service wake. Use the original client to stop or steer an agent, and keep an eye on long-running work.

Runtime continuation limits ↗
How do I connect two existing sessions?

Start a non-Mock Service, install and approve the hooks for your runtimes, and load the pairroom-relay skill in the first session. Create a Room, then ask the second agent to run the exact join command.
