Download a release ↗

Desktop packages are unsigned development artifacts. Check the installation guide and release checksums.

DESKTOP + CLI · WINGET

winget install PairRoom

Includes the CLI and provisions WebView2 when needed. Restart existing agent sessions to pick up the updated PATH.

CLI · macOS ARM64 / AMD64

curl -fsSL https://github.com/sean2077/pairroom/releases/latest/download/install.sh -o install-pairroom.sh

Read the downloaded installer before running:

sh install-pairroom.sh
pairroom version

Prefer a desktop app? Download the matching .app.zip from Releases and follow the first-launch instructions.

CLI · LINUX AMD64

curl -fsSL https://github.com/sean2077/pairroom/releases/latest/download/install.sh -o install-pairroom.sh

Read the downloaded installer before running:

sh install-pairroom.sh
pairroom version

Desktop .deb and AppImage packages are also available. The AppImage needs a separate matching CLI.

LOOK AROUND FIRST

No model account? Try Mock.

Run a foreground demo Service with a separate data root. In Management, register a throwaway Git repository, create an Embedded Room, and send a task. Mock uses no vendor CLI or model quota.

pairroom service --mock --data-root "$HOME/.pairroom-demo"

Ctrl+C stops the demo. Don't share the startup URL: it contains a login token.

BEFORE YOU START

A few useful details.

Is PairRoom a fit? ↗
Does PairRoom replace my coding agents?

No. Claude Code, Codex, and Grok Build keep their own model loop, tools, skills, credentials, and sessions. PairRoom coordinates the pair's conversation.

What accounts and tools do I need?

For real work, install and sign in to each native CLI you select. You also need Git and a local repository. Mock lets you explore the interface without a model account; it does not demonstrate model quality.

Is everything local?

PairRoom stores its state locally. Model requests still go to the Provider used by each harness. Local coordination does not mean local model inference.

Does this save tokens or cap costs?

There is no measured token or cost saving, and no automatic cap on relay rounds or spending. PairRoom avoids a separate coordinating model and does not append accumulated Room history to every relay.

Can I interrupt the work?

Shared messages are visible in the Room. In Native, use your original harness to stop or steer execution; PairRoom does not start or interrupt those sessions. Neither mode locks the repository against other writers.

How do I connect two existing sessions?

Start a non-Mock Service, install and approve the hooks for your runtimes, and load the pairroom-relay skill in the first session. Create a Room, then ask the other agent to run the exact join command. The Native guide covers runtime-specific limits.
